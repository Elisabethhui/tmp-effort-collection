Lesson 0005 · R4

把 Transformer block 接成 Tiny Decoder LM

本课把 R3 的 embedding、causal Transformer block 和 LM head 串成真实的 [B,T] → [B,T,V] 计算路径，仍然优先在 CPU 上验证。

胜利条件：能解释每个 shape，证明未来 token 不会改变过去 logits，并看懂 weight tying 为什么是共享参数。

1. 计算图

input_ids [B,T]
  → token_embedding + position_embedding [B,T,D]
  → TransformerBlock × L [B,T,D]
  → final RMSNorm [B,T,D]
  → lm_head [B,T,V]

TinyDecoderLM 复用了 R3 的 TransformerBlock。causal mask 只允许当前位置读取过去和自己；这是 decoder-only 语言模型的必要约束。PyTorch 的 Transformer building-block 教程可以作为 API 对照，但这里保留了手写 reference 方便面试走读。

2. 三个 shape 观察点

位置shape面试要说清的事
输入[B,T]整数 token id，不是 one-hot
隐藏状态[B,T,D]每个位置都有一个上下文表示
输出[B,T,V]每个位置对词表的未归一化分数

weight tying 时 lm_head.weight 和 token_embedding.weight 是同一个 Parameter，不是训练后复制一份数值。这样可以在测试中用对象身份和梯度共同验证。

4. 动手

.venv/bin/python -m unittest labs/training/test_tiny_lm.py -v
.venv/bin/python -m labs.training.train_tiny_lm --epochs 3 --device cpu

第二条命令使用周期 toy corpus；它的目标是让你看到训练闭环的曲线，不是制造一个有现实语言能力的模型。

5. 回忆题

  1. 为什么 logits 的最后一维是词表大小 V？
  2. 把序列最后一个 token 改掉，为什么过去位置的 logits 应保持不变？
  3. padding key mask 和 causal mask 分别阻止什么信息？
  4. weight tying 共享了什么，仍然没有共享什么？
