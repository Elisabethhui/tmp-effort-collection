Lesson 0004 · R4

一个 logits，为什么要右移一个 token？

本课只完成一个胜利：从 [B,T,V] 的 logits 对齐到下一个 token 的标签，并用有效 token 数量得到可信的 causal LM loss。

今天的边界：只讲目标函数和验证；模型、优化器和 checkpoint 放到 Lesson 0005、Lesson 0006。

1. 预测关系

输入序列 x0, x1, …, xT-1 在位置 t 只能看到当前位置及其之前的 token。位置 t 的 logits 要预测 xt+1，所以最后一个 logits 没有下一个目标。

原张量参与 loss 的切片含义
logits：[B,T,V]logits[:, :-1, :]：[B,T-1,V]位置 0…T-2 的预测分数
labels：[B,T]labels[:, 1:]：[B,T-1]位置 1…T-1 的真实下一个 token

这正是 label_shift.py 中的显式实现；先读代码中的 shape 检查，再看 R4 速查。

2. 有效 token 才能进入分母

prompt、padding 或不可训练的位置用 IGNORE_INDEX = -100 标记。loss 先对有效位置求和，再除以有效 token 数；不能把所有 B×(T-1) 位置直接当分母。

shifted_logits, shifted_labels = shift_causal_logits_and_labels(logits, labels)
loss_sum, valid_tokens = causal_lm_loss_sum_and_count(logits, labels)
loss = loss_sum / valid_tokens

PyTorch 的 autograd 会记录前向操作并在 backward() 时计算梯度；loss 的 shape 和归一化方式仍由我们负责。参阅 Autograd 文档。

3. 动手验证

.venv/bin/python -m unittest labs/training/test_label_shift.py -v

测试会反馈四件事：shift 形状、与 PyTorch cross entropy 的一致性、全是 ignore 时拒绝返回 NaN、以及 loss 能反向传播。
